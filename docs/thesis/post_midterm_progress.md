# 中期答辩后工作推进与优化总结

**时间范围：** 2026 年 3 月 ~ 2026 年 4 月

**摘要：** 中期答辩时，系统仅支持 FY-3D ATP 单产品（温度+气压，2 通道）反演，且仅使用 2025 年 1 月单月数据（13,088 样本）。此后的工作围绕三个方向展开：**引入 WAP 湿大气产品实现三变量联合反演**、**将数据规模从 1 个月扩展至 6 个月**、以及**针对湿度通道的训练策略优化**。最终在 64,116 个样本上训练的模型取得了温度 CC=0.80、气压 CC=0.999、湿度 CC=0.72 的综合反演结果。

---

## 一、中期答辩时的状态

中期答辩（2026 年 3 月初）时，系统的完成状态如下：

| 项目 | 中期状态 |
|------|---------|
| 数据源 | FY-3D GNOS L2 ATP（仅弯曲角 + 温度 + 气压） |
| 数据时间 | 2025 年 1 月（单月） |
| 样本数 | 13,088 个廓线 |
| 输出通道 | 2（温度 + 气压，无湿度） |
| 模型 | EnhancedConditionalUNet1D |
| 温度 CC | ~0.25 |
| 气压 CC | ~0.82 |
| 湿度 | 不可用（ATP 数据不含湿度信息） |

**存在的核心问题：**

1. **缺少湿度反演能力** — ATP 产品不含湿度，无法实现三变量联合反演
2. **数据量不足** — 仅 1 个月数据，模型泛化能力有限
3. **温度精度偏低** — 相关系数仅 0.25，远未达到可用水平
4. **DDIM 采样失败** — 50 步加速采样结果完全不可用

## 二、数据层面的优化

### 2.1 引入 WAP 湿大气产品

中期之后最关键的改进是引入了 FY-3D GNOS **WAP（Wet Atmosphere Profile）** 产品。WAP 是 L2 级湿大气廓线产品，包含经过 1D-Var 反演后的温度、气压和**比湿**数据。

通过将 ATP（弯曲角）与 WAP（温/压/湿标签）**按文件名配对**，构建了完整的三变量训练数据集：

- **输入（X）:** ATP 弯曲角剖面，经 log10 变换 + Z-Score 标准化
- **标签（Y）:** WAP 温度 + log10(气压) + 比湿，Z-Score 标准化
- **配对逻辑:** ATP 与 WAP 文件名仅 `_L2_ATP_` / `_L2_WAP_` 不同，一一对应

新增代码模块：`ro_retrieval/data/atp_wap_process.py`（`ATPWAPProcessor` 类）。

### 2.2 数据规模从 1 个月扩展至 6 个月

| 阶段 | 时间范围 | 原始文件数 | 可用样本数 | 通过率 |
|------|---------|-----------|-----------|-------|
| 中期 (ATP only) | 2025-01 | 15,317 | 13,088 | 85.4% |
| Q1 扩展 (ATP only) | 2025-01 ~ 03 | 42,871 | 37,171 | 86.7% |
| **最终 (ATP+WAP)** | **2025-01 ~ 06** | **74,334** | **64,116** | **86.3%** |

数据扩展过程中解决的工程问题：

1. **数据获取：** 编写了断点续传下载脚本 `utils/download_http_resume.sh`，基于 wget 实现了对 NSMC 数据服务的批量下载（支持断线恢复、失败重试）
2. **多源目录整合：** 编写 `utils/prepare_atp_wap_raw_2025.py`，将 Q1（已有）和 Q2（新下载）的 ATP/WAP 文件通过符号链接统一到 `Data/FY-3/ATP_WAP_2025_RAW/` 目录
3. **大规模处理的稳定性：** 6 万+ 文件的全量处理在单次运行中存在中途退出问题。编写了分块处理脚本 `utils/process_atp_wap_chunked.py`，将数据分为 15 个块（每块 ~5000 个 WAP 文件），支持中间结果缓存和断点续跑，最终合并为训练集

### 2.3 数据预处理改进

相比中期时的 ATP-only 流水线，ATP+WAP 流水线新增了以下处理：

| 改进点 | 说明 |
|--------|------|
| 气压 log10 变换 | 原始气压跨 4 个数量级（0.07~1100 mb），直接标准化会导致分布严重偏斜。改为先取 log10，再 Z-Score 标准化 |
| 湿度通道处理 | 从 WAP 读取 `Shum`（比湿），clip 到非负后纳入标签 |
| 配对完整性校验 | 只保留 ATP 和 WAP 同时存在且 qc=100 的样本 |
| 物理合理性检查 | 新增湿度范围检查（0~50 g/kg）、弯曲角范围检查（1e-6~0.1 rad） |

最终数据集统计：

| 统计量 | 弯曲角 (log10) | 温度 (K) | 气压 (log10 mb) | 湿度 (g/kg) |
|--------|--------------|---------|----------------|------------|
| 均值 | -3.470 | 238.6 | 1.120 | 0.393 |
| 标准差 | 1.120 | 22.2 | 1.093 | 1.664 |

## 三、训练策略优化

### 3.1 湿度加权损失

三变量联合训练中，气压因变化范围集中（log10 变换后）而容易主导损失函数，导致湿度和温度通道学习不充分。针对此问题引入了**变量加权损失**：

```
L_total = w_T · L_T + w_P · L_P + w_Q · L_Q
```

最终配置为 `var_weights = [1, 1, 4]`（温度:气压:湿度 = 1:1:4），显著提升了湿度通道的学习效果。

### 3.2 湿度梯度约束

为使模型生成的湿度剖面在垂直方向上更加平滑、符合物理直觉（湿度随高度递减），额外引入了**湿度梯度正则项**：

```
L_grad = 湿度预测值沿高度方向的梯度惩罚
```

权重设置为 `humidity_grad_weight = 0.05`，在不显著影响主损失的前提下改善了湿度廓线的垂直连续性。

### 3.3 监控目标切换

将 Early Stopping 的监控指标从 `val_loss`（总验证损失）切换为 **`humidity` 分量验证损失**（`monitor_target = humidity`），确保模型保存的最优权重优先保障湿度反演质量。

### 3.4 训练配置汇总

| 参数 | 中期配置 | 最终配置 | 变化原因 |
|------|---------|---------|---------|
| 数据集 | ATP only, 13K 样本 | ATP+WAP, 64K 样本 | 引入 WAP 湿度标签 |
| 输出通道 | 2（温度+气压） | 3（温度+气压+湿度） | 新增湿度反演 |
| var_weights | [1, 1] | [1, 1, 4] | 湿度加权 |
| humidity_grad_weight | — | 0.05 | 梯度约束 |
| monitor_target | val_loss | humidity | 优先保障湿度 |
| patience | 20 | 15 | 加速收敛 |
| epochs | 100 | 50 | 数据量增大后收敛更快 |

## 五、关键发现与结论

1. **数据量扩展带来显著收益** — 从 Q1 到 H1，样本数增加 3 倍以上，湿度 CC 从 0.53 大幅提升至 0.72，温度 CC 从 0.77 提升至 0.80，证明了数据规模对扩散模型反演质量的正向影响

2. **湿度加权策略有效** — `var_weights=[1,1,4]` 结合 `humidity_grad_weight=0.05` 的组合使湿度通道获得了足够的学习梯度，同时未严重损害温度通道

3. **气压精度存在轻微退化** — 气压 RMSE 从 0.049 升至 0.084（仍属于极高精度），这是湿度加权策略下的权衡结果，CC 仍保持在 0.999

4. **DDIM 加速采样仍未解决** — DDIM 50 步采样的结果持续不可用（CC 接近 0），当前只能使用 DDPM 1000 步完整采样，推理速度较慢
