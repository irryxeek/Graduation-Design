# 工程规范说明

本文档用于约束仓库的主线入口、产物边界与最小化自检方式，目标是让毕业设计仓库更接近可维护、可复现的工程形态。

## 1. 主线目录约定

- `ro_retrieval/`
  核心 Python 包。通用逻辑优先放这里，包括数据处理、模型、训练、推理、评估与前端。
- `src/`
  面向任务的命令行入口脚本。推荐保留少量主线脚本，历史脚本或对照脚本可保留但不作为默认入口。
- `docs/`
  论文、答辩和工程说明文档。
- `experiments/`
  论文主线训练、评估和消融实验的结果产物。
- `samples/`
  前端演示或本地调试使用的小样本输入。

## 2. 文件放置原则

- 新的可复用逻辑优先写入 `ro_retrieval/`，避免继续堆积在 `src/`。
- `src/` 中的脚本应尽量薄，只负责参数解析和调用核心包逻辑。
- 大模型权重、批量评估图、临时探针输出不应长期堆在仓库根目录。
- 临时调试结果应放入 `outputs/`、`tmp/` 或独立实验目录，并通过 `.gitignore` 忽略。

## 3. 论文主线入口

当前论文主线统一为：

- 数据处理：`python src/process_data.py --source fy3d_atp_wap ...`
- 训练：`python src/train.py --mode multi --model enhanced ...`
- 评估：`python src/evaluate.py ...`
- 流水线：`python src/run_pipeline.py --all`
- 前端：`streamlit run ro_retrieval/app/streamlit_app.py`

也可使用仓库根目录的 `Makefile`：

```bash
make test
make train-paper
make eval-paper
make app
```

## 4. 结果解释边界

- 主实验和 DDIM 对比结果可视为当前主线稳定结果。
- 表 5-4 应以 `experiments/table5_4_ablation_rerun_20260418T225500Z/` 下的严格复跑结果为准。
- 外部产品对比脚本当前仅作为辅助分析工具，不能替代完整独立验证闭环。

## 5. 最小自检要求

每次修改主线逻辑后，至少完成以下检查：

```bash
make test
python src/evaluate.py --help
python src/run_pipeline.py --help
```

若修改了前端或推理流程，还应补充：

```bash
streamlit run ro_retrieval/app/streamlit_app.py
```

## 6. 提交建议

- 提交前避免把新的临时 `.npy`、`.pth`、日志和缓存文件带入版本控制。
- 论文、README 和主线脚本的默认参数应保持一致。
- 若实验结论发生变化，应同步更新论文修订文档和 README。
